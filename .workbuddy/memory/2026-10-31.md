## 小拾骨骼动画：姿态正确性 + 平滑过渡修复

目标（用户）：确保「对应动作在动、切换不突兀」。

### 环境
- Blender 4.2.12 LTS 已落地 `D:\tools\blender`（headless，沙箱无网，走阿里云镜像）。
- 绑骨脚本 `tools/rig_xiaoshi.py`：导入 `xiaoshi.glb` → 20 骨 → 解析式胶囊距离权重+硬规则（裙摆锁髋、长发锁 Hair、腿沿腿骨紧半径+软过渡防裙摆撕裂）→ 导出 `src/scene/assets/xiaoshi_rigged.glb`（带 skins/IBM/JOINTS_0/WEIGHTS_0）。
- 关键坑：Blender 是 **Z-up**（身高沿 +Z、正面 -Y）；不用 bone-heat（91 万顶点必失败）。

### 本轮改动
1. **动画器重写** `src/scene/characterAnim.js`：从「逐骨低通滤波」改为「**姿态权重交叉淡入**」。逐骨低通会把周期运动（走路/炒菜）压到 ~57% 振幅，动作发虚；新方案每姿态独立权重（指数阻尼 `SMOOTH_BASE=0.004`，settle≈0.6s），周期运动按当前 `t` 求值→振幅完整保留，切姿态是平滑淡入淡出（不突兀）。坐姿 `sit` 作为基底层与打字等叠加。
2. **修路由 bug** `demo.html`：坐姿按钮原 `{state:'working',seated:true}` 被 `resolvePose` 解析成 `type`（点坐姿实际显示打字）。改为 `{pose:'sit',seated:true}` → 返回 `sit`。已核验 sit→sit。
3. **加 `?freezeTime=` 钩子**：把周期动作定格在最大摆幅截图核验。
4. **加大幅度**：走路摆臂 0.42→0.5、打字手/前臂颤动、炒菜画圈，让对应动作更可读。
5. **删除躺姿整身翻倒 hack**：原 `character.rotation.x` 缓动到 -1.25（绕脚底翻），把整个人翻成团、脸压进头发——正是用户说的「动作全到脸部，超级奇怪」。删除后 躺 显示自然放松姿态（真·横躺需住客场景控制器把人放到家具上，未建）。

## 后续：动作「都在脸上」根治 + 姿态接线（本轮实施）

用户反馈：demo.html 里「各种动作基本上都在脸上，十分的诡异」（表现"好像都有"）。落座后续再做。

### 根因（FK 数值实测，非肉眼）
1. **脸撕裂不成立**：重测 91.2 万顶点权重——脸区 100% 归 Head，无空权重；破面感是刘海位移+阴影。
2. **真正根因**：旧姿态表用 UpperArm 的 X 通道前摆短臂（约 24cm），done 手尖距脸中心仅 0.233（脸半径≈0.27）→ 手贴鼻尖。
3. **通道选错**：Shoulder 的 Z 通道（左 +Z / 右 −Z）才是大臂外展/上举的正确关节，实测 Shoulder Z ±1.45 + UpperArm X −0.3 → 手在头侧上方 (±0.23,0.84)、离脸 0.32。
4. **权重盲区**：Shoulder_L 主导顶点含 y 到 0.947 的头侧头发/鳍（h≈0.83），大角度抬肩会拽起该区域。
5. **屋里没接线**：全仓库无人调 `boneTick`，controller 每帧只整身 pitch/roll（头离轴最远摆幅最大）→ 只有脸在动。

### 本轮改动
1. **`src/scene/characterAnim.js` 姿态表重写**：12 个姿态全部改「肩带臂」（Shoulder Z 主导外展/上举，Upperarm X 只做小幅前摆）；头/发摆幅砍半；`done` V 字举手（手在头两侧上方）、`error` 塌肩垂臂低头（弃"抱头"）、`planning/thinking` 从侧面托腮（dFace 0.247，不再横穿脸）、`type` 肘外张手在 (±0.17,0.70,0.17)；`lie` 新增 `root: {pitch:-π/2, y:0.42}` 真·仰卧。
2. **动画器支持 root 姿态**：`tick` 按同一套姿态权重把 `pose.root`（pitch/y）混合后应用到模型根节点，切姿态时整身翻转与骨骼一起淡入淡出；`reset()` 恢复基变换。
3. **`src/scene/glbLoader.js` 运行时权重补丁 `patchHeadWeights`**：bindSkins 里对世界 y>0.80（手臂顶点实测最高 0.78 之上）顶点的 Shoulder_/UpperArm_/Forearm_/Hand_ 权重归还给 Hair（原本带发则）/Head，重新生效——97MB 模型的零成本兜底，免重跑 Blender。
4. **`src/agents/controller.js` 接线**：`pose()` 每帧组 ctx `{state,moving,climbing,walkSpeed,seated:false,pose}` 调 `userData.animate`（眨眼/呆毛）+ `boneTick`；房间→姿态映射（app→stir、browser→lean、其余工位→type）；删掉 root 大幅 pitch/roll（working/planning/thinking/error 只留 1cm 级微弹跳）。

## 致命 bug：DEBUG 未定义把 DSH 主进程干崩

用户重启 DSH 后进入「恢复模式」，报错原文：
```
dsh: fatal uncaught exception: ReferenceError: DEBUG is not defined
    at .../dsh-home3d/lib/index.js:155:9
    at ClientRequest.<anonymous>
```
`dsh desktop host exited with 1` → DSH 判定启动失败，弹恢复界面。

**根因**：我在 `host.js` 里把 `const DEBUG = ...` 写进了 `handler` 函数内部（第185行，缩进4空格），
但 `proxy()` 在第155行也用了 `DEBUG` —— 不在同一作用域。`proxy()` 每次处理请求都会抛
ReferenceError，而这条异常发生在 http client 的响应回调里，**直接打穿 Electron 主进程**
（不是被 try/catch 拦住的普通错误）。

**修法**：把 `DEBUG` 提到模块顶层（`const DEBUG = process.env.DSH_HOME3D_DEBUG === '1'`，
紧跟 sleep 定义），删掉 handler 里那份重复的。构建产物已确认：定义在第33行 indent=0，
使用在 159/193 行，作用域正确。

**验证**（`dsh-home3d/test/crash.test.mjs`，新增）：
模拟真实客户端打 `/events` 与 `/health` 走完整代理路径，监听 uncaughtException /
unhandledRejection。结果 `{"loaded":true,"route":true,"events":200,"health":200,"crashes":[]}`。
这次专门防的就是"ReferenceError 打穿主进程"这个形态。

**教训（要记）**：
1. 往 bundle 里加任何新模块/常量，必须重新 `node build.mjs` 并**实际 import 一次** `lib/index.js`
   验证顶层能执行；只跑 `node --check` 不够（它只查语法，不查作用域）。
2. DSH 的 host 半区崩溃会直接让整个桌面端进恢复模式，比普通插件报错严重得多。
   新增代码里凡是会被异步回调触发的路径（http 回调、timer），都要先确认变量都在
   闭包可达的层级。
3. 写测试别用 SSE 长连接（会让脚本挂住），上游给完数据就 end 即可。
