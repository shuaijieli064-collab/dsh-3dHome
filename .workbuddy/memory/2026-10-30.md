## dsh-home3d 真正装进 DSH 了（官方 CLI 路径打通 + 两个网络坑）

用户诉求：「如何让 dsh 自己通过这个项目加上这个插件」，并开了 VPN 让我重试。

**DSH CLI 在哪**（之前一直没找到，这次从进程命令行挖到）：
- 主程序 `D:/dsh-desktop/DSH NEXT\DSH NEXT.exe`，app 包 `resources\app.asar`
- CLI 入口 = `app.asar\lib\desktop-cli.js`；官方 `dsh.cmd` 的实质是
  `"%DSH_DESKTOP_APP_EXECUTABLE%" --expose-internals "%DSH_DESKTOP_DSH_BOOTSTRAP%" %*`（`ELECTRON_RUN_AS_NODE=1`）。
  那两个环境变量只在 DSH 自带终端里有，普通终端手动设 `DSH_HOME` + `ELECTRON_RUN_AS_NODE=1` 即可调用。
- `dsh plugin --profile <p> add|remove|install ...` 只是把参数转发给 profile 目录里的 pnpm（本机 pnpm 12.15.0，走 corepack）。
- **CLI 只管装、不管启用**：`dependencies`（装了什么）≠ `dsh.profile.bundles`（加载哪些）。profile 里就有 5 个包装了但没进 bundles。启用必须自己加 bundles。

**两个坑（都会让 install 失败，且报错看着像插件的问题）**：
1. 本机 `http_proxy=http://127.0.0.1:59898` 下 `registry.npmjs.org` 返回 `000`、codeload 走隧pnpm 报 `tunnel error`。curl 加 `--noproxy '*'` 直连则 200（开 VPN 后）。→ 跑 CLI 时 `env -u http_proxy -u https_proxy ...`。
2. lockfile 里 `dsh-our-free-model` / `dsh-feiyu-mood` 记的是 **SSH remote**（pnpm 11.21 之前写的），要 GitHub 私钥 → `Permission denied (publickey)`。→ 只针对该进程注入 `GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=url.https://github.com/.insteadOf GIT_CONFIG_VALUE_0=git@github.com:`，git 全局配置不动。
3. `--offline` 无用：本机缓存是 pnpm v11 布局，DSH 用 v12，要求重填。

**最终执行**（成功，2 分钟）：
```
env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY \
  GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=url.https://github.com/.insteadOf GIT_CONFIG_VALUE_0=git@github.com: GIT_TERMINAL_PROMPT=0 \
  <exe> --expose-internals <asar>/lib/desktop-cli.js plugin --profile desktop install
```
